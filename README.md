# Stark Agency · 斯塔克 AI 事务所

一个以 Tony Stark 的实验室与 AI 助手为灵感的本地协作空间。七位 AI 伙伴化身为 Q 版 3D 角色，在办公室里走动、交流，也能通过本机 Codex 执行真实任务。

**Stark** 呼应角色主题，**Agency** 同时表达团队协作与 Agent 的概念。角色的办公室职责是本项目的创作设定，不代表对漫威原作中角色起源的考据。

目前是面向个人使用的桌面应用原型：Electron + TypeScript 桌面入口、原生 JavaScript + Three.js 界面与 Node.js 后台服务，3D 模型由代码构建。保留独立网页模式。界面与角色回复以中文为主。

## 快速开始

开发环境需要 Node.js 22.13 或更高版本，以及 npm 和图形桌面环境。仅体验演示时不需要安装 Codex，也不需要模型密钥。

```sh
cd /你的项目路径/stark-agency
npm ci
npm start
```

`npm start` 编译 TypeScript 并启动 Electron 桌面窗口，自动启动和管理后台服务；无需另开终端运行服务器。首次启动可能需要下载 Electron 运行时。依赖通过锁文件固定版本，首次运行或更新依赖后请先执行 `npm ci`。

```sh
npm run start:web   # 独立网页模式：http://127.0.0.1:4310/
npm run dev:web     # 网页模式，监视服务端文件变更
npm run check       # JavaScript 语法和桌面 TypeScript 类型检查
npm test            # 后台集成、桌面服务鉴权和寻路测试
npm run test:browser # 浏览器场景测试（需要 Chromium）
npm run test:desktop # Electron 窗口与进程生命周期测试（需要图形桌面）
npm run package     # 打包为可运行应用，输出 out/
npm run make        # 生成当前系统的分发包，输出 out/make/
```

桌面版隐藏原生顶部菜单；Windows/Linux 关闭窗口时同时关闭后台，macOS 关闭最后一个窗口后继续驻留，可从 Dock 再次打开或退出。网页模式在终端按 `Ctrl+C` 停止。重启不会自动恢复正在执行的模型任务，历史任务会标为中断，可在连接 Codex 后补充信息继续。

桌面版遵循 Electron 的进程职责分离；完整目录约定、官方参考和发布注意事项见 [桌面架构说明](docs/desktop-architecture.md)。当前提供本地打包配置，尚未配置签名、公证和自动更新。

## 怎样使用

界面采用 1600 × 1000（16:10）的固定游戏布局。窗口缩放时整套界面等比例缩放，全屏或非同比例窗口居中留边，办公室场景铺满画布，顶部状态、底部小队栏和镜头工具以游戏 HUD 悬浮显示；通讯与任务编辑面板按需展开，不挤压场景。点击右上角“全屏”或按 `F11` 切换；macOS 也支持 `Ctrl+Cmd+F`，按 `M` 发布任务、`1–7` 选择伙伴；`Esc` 优先收起面板，面板关闭后退出全屏。动态、对话与长文本可在各自面板内用滚轮翻阅，不显示滚动条。

- 从场景或下方列表选择伙伴；点击空地让其移动，点击家具触发对应活动。聚焦地图后可使用方向键。
- 拖动场景旋转镜头，滚轮缩放；手机单指旋转、双指缩放和旋转。也可以使用工具栏的缩放按钮。
- 使用“复位视角”恢复默认角度与缩放；使用“召集讨论”“回到工位”安排活动。
- “暂停生活”只暂停场景动画，不会停止后台任务。后台任务需在任务面板单独停止。
- 在伙伴档案中直接聊天；在底部输入框给团队安排任务。任务面板支持查看阶段、错误、补充信息和产物。
- 场景不显示角色姓名标签，选中圆环与下方 3D 头像列表帮助辨认伙伴。

### 演示与真实执行

| 模式 | 行为 | 是否调用模型 | 是否产生工作文件 |
| --- | --- | --- | --- |
| 演示 | 展示固定协作流程和示例聊天 | 否 | 不生成工作产物；仍保存任务记录 |
| Codex | 使用本机账户执行任务和角色聊天 | 是 | 可能生成或修改文件 |

日常生活由本地规则驱动，尚未实现由模型自主规划的长期记忆、社交关系或持续工作。

## 团队与任务流程

| 角色 | 办公室职责 | 当前视觉设定 |
| --- | --- | --- |
| Vision | 理解目标、规划与汇报 | 白色服装、金色额饰 |
| Jarvis | 检索资料、整理知识 | 灰发、深色西装 |
| Friday | 实现任务、处理反馈 | 红发、青绿色服装 |
| Ultron | 独立审查、质疑方案 | 银灰机体、红色眼睛 |
| Edith | 检查状态与验证结果 | 深色头发、眼镜、酒红服装 |
| DUM-E | 整理文件、构建与工具操作 | 较大的深灰机械臂、重型底座、黄色轴盖 |
| U | 收集资料、记录证据 | 较小的银灰机械臂、紧凑折臂与夹爪 |

固定团队工作流是 **Vision 规划 → Friday 实现 → Ultron 审查 → Friday 处理反馈 → Vision 汇报**。其余四位暂未进入自动工作流；七位均可直接聊天。工作流按阶段串行执行，并非七个模型同时自主协作。

每阶段使用新的模型线程，通过文字记录传递上下文。直接聊天按角色保存会话 ID；不同角色的聊天会话独立，但共用聊天文件目录。

## 接入本机 Codex

1. 安装官方 Codex CLI，并在终端执行 `codex login`。
2. 确认 `codex` 可以从启动本项目的终端找到。
3. 在页面左下角连接设置或 Codex 模式入口中，点击“连接本机 Codex”。
4. 选择 Codex 模式后输入任务，留意实际执行记录和批准请求。

应用启动 `codex app-server --stdio`，通过 JSON-RPC 通信，使用本机账户和默认模型，不内置 API 密钥。连接依赖本机 CLI 支持代码使用的 App Server 协议；协议模拟测试不能替代真实版本兼容性验证。

当前请求 `workspace-write` 沙盒与 `on-request` 批准策略。仅支持命令执行、文件修改两类批准请求；其他服务端交互会拒绝并记录原因。批准由页面展示的具体请求决定，角色身份不代表额外权限。

主工作流一次接收一个任务。角色聊天可以与团队任务并行，但当前聊天并发控制仍有限，尚存在同一角色同时接收多条请求的保护空档。模型执行的单轮等待上限是 15 分钟；普通 RPC 请求超时为 45 秒。

### 环境变量

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `4310` | 仅网页模式；桌面模式由系统分配空闲端口 |
| `CODEX_BIN` | `codex` | CLI 可执行文件名或完整路径，不是整段 shell 命令 |
| `OFFICE_DATA_DIR` | 桌面：系统用户应用数据目录下 `office`；网页：项目内 `.runtime` | 数据目录，建议使用绝对路径 |
| `DEMO_STEP_MS` | `3200` | 每个演示阶段的等待毫秒数，主要用于测试 |

例如 macOS / Linux：

```sh
PORT=4311 npm run start:web
CODEX_BIN=/你的路径/codex npm start
OFFICE_DATA_DIR=/你的数据路径/stark-agency npm start
```

网页模式改变端口后，访问地址也要改为对应端口。桌面模式不需要手动访问地址。桌面启动时继承的 PATH 可能与终端不同，找不到 Codex 时可在启动应用前设置绝对路径 `CODEX_BIN`。

## 数据、产物与搬迁

桌面版数据默认位于系统用户应用数据目录下的 `Stark Agency/office`。首次桌面启动不会自动导入项目内 `.runtime`，也不会改写已有历史任务；如果需要沿用原数据，可在启动前将 `OFFICE_DATA_DIR` 指向原数据目录的绝对路径。不要同时启动两个使用同一数据目录的服务。

```text
<数据目录>/
├── state.json             任务、消息、活动及角色聊天会话 ID
├── projects/<任务 ID>/    每个任务自己的工作目录
│   └── OFFICE-HANDOFF.md   工作流成功结束时写入的阶段汇总
└── chat-workspace/        所有直接聊天共享的文件工作目录
```

历史记录目前保留最近 50 个任务、200 条消息、150 条活动，旧工作目录不会自动清理。生活动态和角色位置不持久化，刷新后重置。备份时应停止服务并备份整个数据目录；不要只备份 `state.json`。

**搬迁或改名的现有限制：** 任务记录保存了工作目录的绝对路径，Codex 会话也可能关联原目录；当前没有自动迁移逻辑。从 `agent` / `stark-lab` 改名为 `stark-agency` 后，旧任务的产物预览和继续执行可能失效。恢复旧任务前需要核对并迁移目录记录。希望保留历史时，请先备份数据，不要直接删除 `.runtime`。从一开始配置固定的绝对 `OFFICE_DATA_DIR` 可以减少以后改名带来的影响，但不会自动修复旧记录。

产物预览仅允许访问任务目录内部的真实文件，会校验符号链接目标。文本或常见图片的预览上限为 512,000 字节；HTML 以源码展示。列表最多显示 80 个文件，目录遍历深度有限，并跳过隐藏文件、`node_modules` 和 `vendor`。预览或列表未显示不代表磁盘中不存在文件。

`completed` 表示各阶段都返回了完成状态，并不等于应用已独立验证所有验收标准。请查看汇总、实际文件和验证记录。

## 项目结构

```text
src/
├── main/              Electron 主进程（TypeScript）：窗口、菜单、后台生命周期
├── preload/           沙盒预加载（TypeScript）：受限 contextBridge 接口
├── backend/           Node.js 后台：HTTP/SSE、任务、角色与 Codex 桥接
└── renderer/          浏览器界面、Three.js 场景、模型、寻路及静态资源
scripts/               开发检查脚本
tests/                 后台、寻路、浏览器和 Electron 测试
docs/                  架构与开发约定
server.mjs             独立网页模式启动入口
forge.config.cjs       Electron Forge 分发配置
tsconfig.json          桌面 TypeScript 编译配置
dist/                  桌面编译产物（不提交）
out/                   应用及分发包（不提交）
```

浏览器使用 Three.js / WebGL 2 渲染立体角色和家具，支持阴影、深度遮挡和环绕镜头。模型与家具位置对应既有网格，继续使用 A* 寻路、占位及下一步预留。DUM-E 和 U 均使用可活动机械臂，DUM-E 更大。头像由同一套 3D 模型渲染。Three.js 从本机依赖目录的白名单路由提供，不依赖运行时 CDN。

如果浏览器无法创建 WebGL 2 上下文，会明确提示并进入二维兼容视图；可检查浏览器硬件加速设置。3D 拖动期间不触发点击移动，旋转到办公室背面时会隐藏后墙。暂停生活时仍可旋转和缩放镜头。

## 测试与验证范围

`npm test` 使用独立临时数据目录、14310 端口和模拟 Codex 进程，不读取真实账户凭证、不调用付费模型。覆盖串行任务、取消、阶段状态、补充信息、文件预览、持久化、请求来源检查、角色聊天、寻路、集合、暂停及多人占位避让。测试端口被占用时需要先释放；目前不自动选择空闲端口。

`npm run check` 检查 JavaScript 语法和桌面 TypeScript 类型。测试通过不代表真实 CLI 版本完全兼容，也不代表所有移动布局、浏览器、长时间运行和像素动作都已验证。模型外观和交互布局还需浏览器目视检查。

新增可选的浏览器测试，使用独立临时数据目录和 14311 端口：

```sh
npx playwright install chromium
npm run test:browser
```

如果已有 Chromium，可用 `CHROME_BIN=/完整路径/Chromium npm run test:browser` 指定可执行文件。测试使用隔离的无头浏览器验证 3D 启动、旋转、缩放、复位、拖动与点击区分、角色移动和手机布局，不使用个人浏览器数据。

## 常见问题

- **4310 端口被占用：** 停止旧服务，或使用 `PORT=4311 npm run start:web`。
- **找不到 Codex：** 在同一终端确认 CLI 可用，或设置 `CODEX_BIN` 为完整路径。
- **登录后仍显示未连接：** 再点击连接；也检查服务启动时使用的用户环境。
- **任务停在等待信息：** 在任务面板填写缺少的信息后继续；重试需要先连接 Codex。
- **批准请求等待中：** 检查页面中的具体操作，再批准或拒绝。
- **重启后显示中断：** 服务不会自动续跑；连接后补充信息继续。
- **改名后旧产物打不开：** 检查上文“数据、产物与搬迁”的绝对路径限制。
- **改了前端却没有变化：** 刷新页面；桌面版刷新窗口；修改主进程或预加载代码后重新运行 `npm start`。`npm run dev:web` 不提供浏览器热更新。

## 使用边界与后续方向

服务仅监听 `127.0.0.1`，检查 Host 和 Origin；桌面版额外使用每次启动生成的 HttpOnly 会话 Cookie，但没有账户登录、多用户隔离或公网部署能力。它适合可信的个人本机环境；独立网页模式没有会话鉴权，同机程序仍能访问接口。桌面会话鉴权也不构成针对同一操作系统用户下恶意程序的强隔离。当前也没有完整的审计系统、自动备份、聊天取消入口、持久化作业队列或项目迁移工具。

建议后续先处理目录迁移与聊天并发，再拆分服务端任务模块，补充重连、批准和异常中断测试，最后扩展多角色工作流、长期记忆与自定义角色。当前已知问题还包括聊天线程恢复失败时静默新建会话，以及完成状态缺少应用层独立验收。

角色名称及实验室主题取自用户指定的漫威 / Tony Stark 灵感，本项目没有声明与漫威官方存在关联。仓库当前未提供 LICENSE；公开分发前需明确代码、历史生成图片与角色素材各自的授权方式。
